✓ 做得好的地方
  1. 决策型注释近乎教科书级：每个设计决策都带「为什么 + 踩坑实测」，如网易云 fee 字段行为表、CDN https→http 302、120Hz 下衰减速度翻倍等，维护者可以直接接手。
  2. 测试策略极其务实：299 个纯 JVM 单测覆盖歌词解析/匹配打分/去重/排序/均衡器 DSP/物理模拟；刻意用泛型纯函数（findDuplicatesIn、nextOnlineHistory）绕开 Android Uri 桩，让核心逻辑可测。
  3. 性能意识深入骨髓：release 强制 R8、Baseline Profile + profileinstaller、Compose 稳定性报告、@Immutable 防全屏掉帧、物理模拟用解析解实现精确帧率无关（附数学证明）、EqBus 用 revision 避免每块重算系数。
  4. 音频链路顺序有讲究：均衡器在取样器之前 → 可视化读的是「用户实际听到的声音」；软件 EQ 绕开 ColorOS 拒绝 AudioEffect 的兼容坑，全机型可用。
  5. 权限与隐私克制：WRITE_EXTERNAL_STORAGE 用 maxSdkVersion=28 限死、MediaStore IS_PENDING 免权限落盘、三个联网功能全部默认关闭、明文 HTTP 只放行 CDN 单域而非全局。
  6. 边界处理扎实：remoteSongId 用 FNV-1a 64 位并附生日悖论计算、负数 id 约定防与 MediaStore 撞车、在线歌持久化用 StoredOnlineSong 而非会过期的 Uri、下载校验 Content-Length 防半首歌。
✗ 值得优化的地方（按严重度）
  1. P0 安全 · 签名密钥曾明文入库（已修复）：审查时发现 sonance.keystore 被 git 跟踪，且 storePassword/keyPassword 明文写死在 build.gradle.kts、.gitignore 注释还注明「故意纳入」。已处理：密钥文件与口令移出版本管理（改从 local.properties 读取，缺配置时回退 debug 签名），并用 filter-branch 重写历史抹除全部残留。生产签名密钥仍需另行轮换。
  2. P1 合规 · KGM/VPR 解密 + 未公开接口：PrivateAudioRestorer 实现私有 DRM 容器脱壳（LockedFormat 注释却写「不会去解密」，自相矛盾）；网易云搜索/取流走未公开接口 + 浏览器 UA 伪装，改版即失效，有《著作权法》技术措施条款风险。注释需与实现一致，风险需正视。
  3. P1 结构 · 上帝对象与巨型文件：SonanceViewModel 2156 行承载曲库/在线/还原/设置全部状态；FullPlayer 1467、SettingsScreen 1390、Visualizer 1133。按域拆分 ViewModel 或引入 use-case 层是必然方向。
  4. P2 存储 · SharedPreferences 膨胀：播放次数每首歌一个键、收藏/隐藏/下载键全堆 XML，几千首歌时读写退化；allPlayCounts 遍历 sp.all 是缓解非根治，应考虑 Room/DataStore。
  5. P2 质量门禁 · lint 关闭：abortOnError=false + checkReleaseBuilds=false 等于 lint 不设防；无 instrumented/UI 测试，回归全押在手测 + 299 个纯逻辑单测。
  6. P2 工程 · 其他：无 README 上手文档；依赖偏旧（compose-bom 2024.10、media3 1.5、compileSdk 35）；build/ 残留 210MB 磁盘产物；可观测性仅 Log 无崩溃上报。
总评
单人项目的工程质量显著高于平均水准：注释即文档、测试钉住最容易静默出错的部分、性能优化有量化依据（实测数据而非感觉）。核心短板不在代码写法，而在工程治理——签名密钥入库已修复（历史已重写、密钥另行轮换）；巨型 ViewModel 和关闭的 lint 会在功能继续膨胀后成为改不动的手脚架；解密 DRM 容器与未公开接口是产品化之前必须想清楚的风险敞口。
